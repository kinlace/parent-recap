# Setup internals

What each setup step does on the Mac, what it writes and where, where each secret lives, and how `family-brief uninstall` reverses it. It's for maintainers: when a setup step starts writing something new, add it here and teach uninstall to remove it, so the two stay in step. The family-facing steps are in [skills/setup/SKILL.md](../skills/setup/SKILL.md); the secrets and the data flow, in [SECURITY.md](../SECURITY.md).

## Setup's record

Every step that creates something adds it to `~/.family/install-record.json` (owner-only), through `family_brief.install_record`:

| Kind          | Added by                          | Value                                                       |
| ------------- | --------------------------------- | ----------------------------------------------------------- |
| `program`     | `install.sh`                      | The program folder, `~/FamilyBrief/app` by default           |
| `logs`        | `install.sh`                      | `~/FamilyBrief/logs`                                         |
| `plugin`      | `install.sh`, run from `~/FamilyBrief/plugin` | That plugin copy                                 |
| `codex-skill` | `install.sh --codex`              | `~/.agents/skills/parent-recap-setup` and `parent-recap-manage` |
| `launchd`     | `family-brief schedule install`   | Each job's plist in `~/Library/LaunchAgents`                 |
| `keychain`    | Storing a Gmail App Password      | The Keychain account, `gmail-imap-<address>`                 |

Installs from 0.4.1 and older have no record. Uninstall then looks in the places listed below, says the record is missing, and lists what it found for the family to check before confirming. With or without a record, it checks that each item is this install's before it lists it for removal.

## Where each secret lives

| Secret                         | Where                                                  | Uninstall                                       |
| ------------------------------ | ------------------------------------------------------ | ----------------------------------------------- |
| Gmail App Password             | Keychain `family-brief` / `gmail-imap-<address>`       | Deleted. The family deletes it at Google        |
| Claude token                   | Keychain `family-brief` / `claude-oauth-token`         | Deleted                                         |
| Anthropic API key (if used)    | Keychain `family-brief` / `anthropic-api-key`          | Deleted                                         |
| ChatGPT login                  | `~/.codex`, Codex's own                                | Not touched                                     |
| Wilma login                    | `~/.config/wilmai/config.json`, the wilma CLI's own    | Not touched; uninstall says how to delete it    |
| MyClub links                   | `~/.family/config.yaml`                                | Deleted with the config                         |
| Google Calendar app file       | `~/.family/calendar_credentials.json`                  | Deleted                                         |
| Google Calendar token          | `~/.family/calendar_token.json`                        | Deleted. The family removes the access at Google |

Uninstall checks a Keychain item is there with `security find-generic-password` without `-w`, so it never reads a secret, and prints only the service and account.

## How uninstall works

`family-brief uninstall` first lists everything above that it finds, and removes nothing. Something in those places that isn't this install's stops it, before it removes anything: a launchd job with Parent Recap's label that runs another program, a config Parent Recap didn't write, a program folder or Codex skill of the same name that isn't Parent Recap's, or a run that's going. Files that only share a folder with Parent Recap's, such as a note in `~/FamilyBrief`, don't stop it: it lists them under "Left as it is" and doesn't touch them.

It removes only after the family confirms: `--confirm` with `--keep-archive` or `--remove-archive`, or, run in Terminal, its own two questions. The archive is the dated Briefs in the archive folder and `weekend_events/`. It removes in this order: the launchd jobs (so nothing starts mid-way), the wake schedule, the Keychain items, the Codex skills, the plugin copy, the archive if chosen, the config and state, the logs, the program, and the record last, which stays if anything couldn't be removed so the next try still knows what's left. Folders it leaves empty are removed too. It never touches the family's accounts; it ends with where they can delete the App Password and the Google Calendar access themselves.

After it, `~/.family/config.yaml` is gone, so setup starts again from the beginning on the same Mac.
