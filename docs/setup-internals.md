# Setup internals

What each setup step does on the Mac, what it writes and where, where each secret lives, and how `family-brief uninstall` reverses it. It's for maintainers: when a setup step starts writing something new, add it here and teach uninstall to remove it, so the two stay in step. The family-facing steps are in [skills/setup/SKILL.md](../skills/setup/SKILL.md); the secrets and the data flow, in [SECURITY.md](../SECURITY.md).

## Setup's record

Every step that creates something adds it to `~/.family/install-record.json` (owner-only), through `family_brief.install_record`:

| Kind          | Added by                          | Value                                                       |
| ------------- | --------------------------------- | ----------------------------------------------------------- |
| `program`     | `install.sh`                      | The program folder, `~/FamilyBrief/app` by default           |
| `logs`        | `install.sh`                      | `~/FamilyBrief/logs`                                         |
| `plugin`      | `install.sh`, run from `~/FamilyBrief/plugin` | That plugin copy                                 |
| `codex-skill` | `install.sh --codex`              | `~/.agents/skills/parent-recap-setup` and `parent-recap-manage` |
| `launchd`     | `family-brief schedule install`   | Each job's plist in `~/Library/LaunchAgents`                 |
| `keychain`    | Storing a Gmail App Password      | The Keychain account, `gmail-imap-<address>`                 |

Installs from 0.4.1 and older have no record. Uninstall then looks in the places listed below, says the record is missing, and lists what it found for the family to check before confirming. With or without a record, it checks that each item is this install's before it lists it for removal.

## Each step

The steps are in the order the setup skill's six phases (Welcome, Connect, Working, Check, First Brief, Finish) run them.

| Step                  | What it writes                                                                                                                                                                                          | How uninstall reverses it                                                                                                                                                                                       |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The setup page        | `family-brief setup page` serves the page from the program's own files in `family_brief/page/`, on 127.0.0.1, until 30 minutes without a request. It writes only through `family-brief setup save`: the config and setup's progress, below | Nothing of its own to reverse                                                                                                                                                                                    |
| Welcome               | Nothing                                                                                                                                                                                                 | Nothing to reverse                                                                                                                                                                                              |
| Connect: the Mac      | Whatever the family installs with Homebrew or npm: Python, Node, the `claude` CLI                                                                                                                       | Left alone: they're general tools other programs use                                                                                                                                                             |
| Connect: install      | `install.sh`: `~/FamilyBrief/app` (the program, its `.venv` and `VERSION`), `~/FamilyBrief/logs`, the folder `~/.family`, and the record. With `--codex`, `~/.agents/skills/parent-recap-setup` and `parent-recap-manage` | Removes the program last of all, since uninstall runs from it, but only if its `pyproject.toml` names `family-brief`. Removes the logs. Removes each Codex skill only if its `SKILL.md` has that skill's name and the installer's "installed in Codex" note |
| Connect: Wilma        | The wilma CLI (`npm i -g @wilm-ai/wilma-cli`) and its sign-in, `~/.config/wilmai/config.json`, with the Wilma password Base64-encoded. `family-brief setup wilma` runs the sign-in from a script in a temporary folder, removed when the step ends | Left alone, since the wilma CLI is its own program. Uninstall prints the commands to delete both, and says why it matters                                                                                       |
| The config            | `~/.family/config.yaml` (600), written by `family-brief setup save` from the answers, first after Wilma and again at Check. Later changes leave backups next to it, `config.yaml.bak-<date>`                                                                                                         | Removes the config and its backups, but only if the config reads as a Parent Recap config (it has Kids, and Gmail or email settings)                                                                             |
| Setup's progress      | `~/.family/setup-progress.json` (600), written by `family-brief setup save` at each phase and each Source's status, so the setup page and the chat setup resume at the same step. It also keeps the page's Welcome choice of partner until the parent's own address is known. On Welcome the page checks the AI with `claude auth status` or `codex login status`, which change nothing                                                                     | Removes it                                                                                                                                                                                                      |
| Connect: Gmail        | `family-brief setup gmail` (or the older `scripts/setup_gmail_imap.py`): Keychain, service `family-brief`, account `gmail-imap-<address>`. In the family's Google account: the App Password          | Deletes the Keychain item (macOS may ask the family to allow it). Says where to delete the App Password in the Google account                                                                                    |
| Connect: AI login     | Claude: `family-brief setup claude` (or the older `scripts/setup_claude_token.py`): Keychain `family-brief` / `claude-oauth-token` (or `anthropic-api-key`). It runs `claude setup-token` in a Terminal window from a script in a temporary folder, removed when the step ends, because `setup-token` signs in on an interactive screen that needs a real terminal and can't have its output captured. ChatGPT: nothing, Codex keeps its own login in `~/.codex`. In Working, `family-brief language`: `~/.family/languages/`             | Deletes the Keychain items and the languages folder. Never touches `~/.codex`                                                                                                                                    |
| Connect: WhatsApp     | System Settings: the program's Python in App Management (or Full Disk Access), and its one-time Allow for data from other apps. `family-brief setup whatsapp` reads only through `bg` jobs, opens Finder and App Management when the Python can't read yet, and writes nothing. Each `bg` command: a one-off launchd job `com.family.bg.<pid>` in a temporary folder, removed when it ends | Can't change System Settings, so it says where to remove the Python. The `bg` jobs are already gone                                                                                                               |
| Connect: MyClub       | `family-brief setup myclub --kid <name>` (or the older `scripts/setup_myclub.py`): each Kid's link, in `~/.family/config.yaml`                                                                                                                                                           | Goes with the config                                                                                                                                                                                             |
| Manage: Calendar      | Setup uses `ics`, which writes nothing. Manage can switch to `google` later: `~/.family/calendar_credentials.json` (the Google app file) and `~/.family/calendar_token.json`, and access in the family's Google account | Removes both files. Says where to remove Parent Recap's access in the Google account                                                                                                                             |
| Working: health check | Nothing                                                                                                                                                                                                 | Nothing to reverse                                                                                                                                                                                              |
| Check: pilot feedback | Config only                                                                                                                                                                                             | Goes with the config                                                                                                                                                                                             |
| First Brief           | Each run: `~/FamilyBrief/<date>.md` and `<date>.raw.json` (the archive), `~/.family/state.json`, `~/.family/run.lock`, the logs and model diagnostics in `~/FamilyBrief/logs/`                           | Removes state, run lock and logs. When the config puts the archive in a folder of the family's own, such as `~/Documents`, only the jobs' `run-` and `weekend-events-` log files go from its `logs/`. The archive is kept or removed as the family chooses. Stops if a run holds the run lock |
| Finish: schedule      | `~/Library/LaunchAgents/com.family.brief.plist` (and `com.family.weekend-events.plist` with Weekend Picks), loaded with `launchctl`. `pmset repeat wakeorpoweron MTWRFSU <5 minutes before>`, through macOS's administrator dialog (or the family's `sudo` in Terminal without a desktop session) | Unloads and deletes each plist, but only if it runs `<program>/.venv/…/python -m family_brief`. Cancels the wake schedule (`pmset repeat cancel`, through macOS's administrator dialog) only if it's the one setup gives and nothing else is repeating, since cancelling removes every repeating event |
| Weekend Picks         | Not in setup: manage turns them on. Config only. Each Friday's picks go to `~/FamilyBrief/weekend_events/`                                                                                                                                  | The folder is part of the archive (below)                                                                                                                                                                        |
| The plugin            | Claude Code keeps its copy under `~/.claude/plugins` (`get.sh --claude` adds the marketplace and installs it there). `get.sh --codex` downloads the `stable` branch to `~/FamilyBrief/plugin`, replacing what's there only if it's Parent Recap's; zip installs unzip it there                                                                                    | Removes `~/FamilyBrief/plugin` if its `.claude-plugin/plugin.json` names `parent-recap`. Says to remove the Claude Code plugin with `/plugin uninstall parent-recap@kinlace` and `/plugin marketplace remove kinlace` |

## Where each secret lives

| Secret                         | Where                                                  | Uninstall                                       |
| ------------------------------ | ------------------------------------------------------ | ----------------------------------------------- |
| Gmail App Password             | Keychain `family-brief` / `gmail-imap-<address>`       | Deleted. The family deletes it at Google        |
| Claude token                   | Keychain `family-brief` / `claude-oauth-token`         | Deleted                                         |
| Anthropic API key (if used)    | Keychain `family-brief` / `anthropic-api-key`          | Deleted                                         |
| ChatGPT login                  | `~/.codex`, Codex's own                                | Not touched                                     |
| Wilma login                    | `~/.config/wilmai/config.json`, the wilma CLI's own    | Not touched; uninstall says how to delete it    |
| MyClub links                   | `~/.family/config.yaml`                                | Deleted with the config                         |
| Google Calendar app file       | `~/.family/calendar_credentials.json`                  | Deleted                                         |
| Google Calendar token          | `~/.family/calendar_token.json`                        | Deleted. The family removes the access at Google |

Uninstall checks a Keychain item is there with `security find-generic-password` without `-w`, so it never reads a secret, and prints only the service and account.

## How uninstall works

`family-brief uninstall` first lists everything above that it finds, and removes nothing. Something in those places that isn't this install's stops it, before it removes anything: a launchd job with Parent Recap's label that runs another program, a config Parent Recap didn't write, a program folder or Codex skill of the same name that isn't Parent Recap's, or a run that's going. Files that only share a folder with Parent Recap's, such as a note in `~/FamilyBrief`, don't stop it: it lists them under "Left as it is" and doesn't touch them.

It removes only after the family confirms: `--confirm` with `--keep-archive` or `--remove-archive`, or, run in Terminal, its own two questions. The archive is the dated files (`<date>.md`, `<date>.raw.json`) in the archive folder and the Weekend Picks folder, and nothing else in them. It removes in this order: the launchd jobs (so nothing starts mid-way), the wake schedule, the Keychain items, the Codex skills, the plugin copy, the archive if chosen, the config and state, the logs, the program, and the record last, which stays if anything couldn't be removed so the next try still knows what's left. Before it starts, it adds every Keychain item it found to the record, so one macOS refused to delete is found again after the config that named it is gone. Of the folders setup makes (`~/FamilyBrief`, its `weekend_events/`, `~/.family`), those left empty are removed too; a folder of the family's own that held the archive stays. It never touches the family's accounts; it ends with where they can delete the App Password and the Google Calendar access themselves.

After it, `~/.family/config.yaml` is gone, so setup starts again from the beginning on the same Mac.
