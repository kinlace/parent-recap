# Setup internals

What each setup step does on the Mac, what it writes and where, where each secret lives, and how `family-brief uninstall` reverses it. It's for maintainers: when a setup step starts writing something new, add it here and teach uninstall to remove it, so the two stay in step. The family-facing steps are in [skills/setup/SKILL.md](../skills/setup/SKILL.md); the secrets and the data flow, in [SECURITY.md](../SECURITY.md).

## Setup's record

Every step that creates something adds it to `~/.family/install-record.json` (owner-only), through `family_brief.install_record`:

| Kind          | Added by                          | Value                                                       |
| ------------- | --------------------------------- | ----------------------------------------------------------- |
| `program`     | `install.sh`                      | The program folder, `~/FamilyBrief/app` by default           |
| `logs`        | `install.sh`                      | `~/FamilyBrief/logs`                                         |
| `plugin`      | `install.sh`, run from `~/FamilyBrief/plugin` | That plugin copy                                 |
| `codex-skill` | `install.sh --codex`              | `~/.agents/skills/parent-recap-setup` and `parent-recap-manage` |
| `launchd`     | `family-brief schedule install`   | Each job's plist in `~/Library/LaunchAgents`                 |
| `keychain`    | Storing a Gmail App Password      | The Keychain account, `gmail-imap-<address>`                 |
| `wilma-cli`   | Installing the wilma CLI: the setup page, or `family-brief setup wilma` | `@wilm-ai/wilma-cli`                    |
| `wilma-profile` | Signing in to Wilma on the setup page, or in `setup wilma`'s Terminal window | The profile's id in the CLI's config, `<Wilma address>\|<username>`, never the password |
| `claude-plugin` | `get.sh --claude`, or the setup page once Welcome is saved with Claude | `parent-recap@kinlace`                   |
| `claude-marketplace` | The same                    | `kinlace`                                                     |

The last four go in only when setup installed them: a wilma CLI, Wilma profile, plugin or marketplace that was already there in any form (such as a `kinlace` marketplace from an unzipped release) isn't recorded, so uninstall leaves it. `get.sh --claude` runs before the program is installed, so it writes its two kinds into the file itself.

Installs from 0.4.1 and older have no record. Uninstall then looks in the places listed below, says the record is missing, and lists what it found for the family to check before confirming. With or without a record, it checks that each item is this install's before it lists it for removal.

## Each step

The steps are in the order the setup skill's six phases (Welcome, Connect, Working, Check, First Brief, Finish) run them.

| Step                  | What it writes                                                                                                                                                                                          | How uninstall reverses it                                                                                                                                                                                       |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The setup page        | `family-brief setup page` serves the page from the program's own files in `family_brief/page/`, on 127.0.0.1, until 30 minutes without a request, until every outcome of `family-brief setup status` is true, or until the parent presses Finish for now after a try at Finish; then it says in Terminal that the window can be closed. It writes only through `family-brief setup save` (the config and setup's progress, below), and the Gmail, Wilma and Claude sign-ins and the MyClub links the way their own steps keep them, below, and the first Brief's delivery in `~/.family/state.json` (First Brief, below). Its WhatsApp step reads and opens System Settings the way `setup whatsapp` does, below. "Continue in the chat" opens Claude Code at the setup skill in a Terminal window, from a script in a temporary folder removed when the page stops, and writes nothing else; for Codex it only shows what to type | Nothing of its own to reverse                                                                                                                                                                                    |
| Welcome               | Nothing                                                                                                                                                                                                 | Nothing to reverse                                                                                                                                                                                              |
| Connect: the Mac      | Whatever the family installs with Homebrew or npm: Python, Node, the `claude` CLI                                                                                                                       | Left alone: they're general tools other programs use                                                                                                                                                             |
| Connect: install      | `install.sh`: `~/FamilyBrief/app` (the program, its `.venv` and `VERSION`), `~/FamilyBrief/logs` with an `install-<date>-<time>.log` of pip's output for each install, the folder `~/.family`, and the record. With `--codex`, or from the setup page once Welcome is saved with ChatGPT, `~/.agents/skills/parent-recap-setup` and `parent-recap-manage` | Removes the program last of all, since uninstall runs from it, but only if its `pyproject.toml` names `family-brief`. Removes the logs. Removes each Codex skill only if its `SKILL.md` has that skill's name and the installer's "installed in Codex" note |
| Connect: Wilma        | The wilma CLI, version 1.6.2 (`npm i -g @wilm-ai/wilma-cli@1.6.2`, which the setup page and `family-brief setup wilma` run themselves when it's missing), and its sign-in, `~/.config/wilmai/config.json`, with the Wilma password Base64-encoded. `family-brief setup wilma` runs the sign-in from a script in a temporary folder, removed when the step ends. The setup page writes that file itself, the way the CLI does, keeping the CLI's other profiles, then runs `wilma kids list`, and puts the file back as it was if the sign-in fails (ADR 0008). It reads the town list from the CLI's own copy. Either way the town goes in the config as `city`. The CLI and a profile new to its config go in the record | Removes the profile the record has from `config.json`, keeping the CLI's other profiles, and the file and its folder once none are left. Uninstalls the CLI with `npm uninstall -g @wilm-ai/wilma-cli` if the record has it. A CLI or profile from before setup is left alone: uninstall then prints the commands to delete them, and says why it matters |
| The config            | `~/.family/config.yaml` (600), written by `family-brief setup save` from the answers, first after Wilma and again at Check. Later changes leave backups next to it, `config.yaml.bak-<date>`                                                                                                         | Removes the config and its backups, but only if the config reads as a Parent Recap config (it has Kids, and Gmail or email settings)                                                                             |
| Setup's progress      | `~/.family/setup-progress.json` (600), written by `family-brief setup save` at each phase and each Source's status, so the setup page and the chat setup resume at the same step. It also keeps the page's Welcome choice of partner until the parent's own address is known, when the page's Gmail step saves the Recipients. Once the page can read WhatsApp, it keeps the groups found there too, as `whatsapp_chats`, and in Working the Gmail senders it read, as `gmail_senders`, both for the check page. Skipping Wilma on the page also saves `wilma.enabled: false` in the config. On Welcome the page checks the AI with `claude auth status` or `codex login status`, which change nothing                                                                     | Removes it                                                                                                                                                                                                      |
| Connect: Gmail        | `family-brief setup gmail` (or the older `scripts/setup_gmail_imap.py`), or the setup page's own fields, which test and store it the same way: Keychain, service `family-brief`, account `gmail-imap-<address>`. In the family's Google account: the App Password          | Deletes the Keychain item (macOS may ask the family to allow it). Says where to delete the App Password in the Google account                                                                                    |
| Connect: AI login     | Claude: `family-brief setup claude` (or the older `scripts/setup_claude_token.py`): Keychain `family-brief` / `claude-oauth-token` (or `anthropic-api-key`). It runs `claude setup-token` in a Terminal window from a script in a temporary folder, removed when the step ends, because `setup-token` signs in on an interactive screen that needs a real terminal and can't have its output captured. The setup page runs `claude setup-token` itself in a pseudo-terminal, reads the token from its screen, tests and stores it the same way, and writes no file; if that fails it opens the same Terminal window, from a temporary folder removed once the token is saved or the page stops, and takes the token in its own field. ChatGPT: nothing, Codex keeps its own login in `~/.codex`. When Codex is signed out, the setup page runs `codex login`, which signs in to ChatGPT in the browser and writes there. In Working, `family-brief language`: `~/.family/languages/`             | Deletes the Keychain items and the languages folder. Never touches `~/.codex`                                                                                                                                    |
| Connect: WhatsApp     | System Settings: the program's Python in App Management (or Full Disk Access), and its one-time Allow for data from other apps. `family-brief setup whatsapp` reads only through `bg` jobs, opens Finder and App Management when the Python can't read yet, and writes nothing. Each `bg` command: a one-off launchd job `com.family.bg.<pid>` in a temporary folder, removed when it ends | Can't change System Settings, so it says where to remove the Python. The `bg` jobs are already gone                                                                                                               |
| Connect: MyClub       | `family-brief setup myclub --kid <name>` (or the older `scripts/setup_myclub.py`), or the setup page's own field, which checks and saves it the same way: each Kid's link, in `~/.family/config.yaml`. | Manage: Calendar      | Setup uses `ics`, which writes nothing. Manage can switch to `google` later: `~/.family/calendar_credentials.json` (the Google app file) and `~/.family/calendar_token.json`, and access in the family's Google account | Removes both files. Says where to remove Parent Recap's access in the Google account                                                                                                                             |
| Working: health check | Nothing. The setup page reads the Gmail senders in Working as `discover gmail-senders --json` does, and runs doctor's checks, but not the scheduled job's, once the check page is confirmed; it saves what's confirmed through `family-brief setup save`, above                                                                                                                                                                                           | Nothing to reverse                                                                                                                                                                                              |
| Check: pilot feedback | Config only                                                                                                                                                                                             | Goes with the config                                                                                                                                                                                             |
| First Brief           | Each run: `~/FamilyBrief/<date>.md` and `<date>.raw.json` (the archive), `~/.family/state.json`, `~/.family/run.lock`, the logs and model diagnostics in `~/FamilyBrief/logs/`. The setup page instead makes the Brief with `family-brief bg run --preview --lookback-hours 72`, which writes no archive, state or run lock (only a failed model call's diagnostics, as any run does), keeps it in memory, and on "Send it to me" emails it to the setup parent only and records that in `~/.family/state.json`, holding `~/.family/run.lock` while it does | Removes state, run lock and logs. When the config puts the archive in a folder of the family's own, such as `~/Documents`, only the jobs' `run-` and `weekend-events-` log files go from its `logs/`. The archive is kept or removed as the family chooses. Stops if a run holds the run lock |
| Finish: schedule      | `~/Library/LaunchAgents/com.family.brief.plist` (and `com.family.weekend-events.plist` with Weekend Picks), loaded with `launchctl`. `pmset repeat wakeorpoweron MTWRFSU <5 minutes before>`, through macOS's administrator dialog (or the family's `sudo` in Terminal without a desktop session). The setup page's Finish installs the same, through the same step, and replaces another repeating wake schedule only once the parent presses Replace it | Unloads and deletes each plist, but only if it runs `<program>/.venv/…/python -m family_brief`. Cancels the wake schedule (`pmset repeat cancel`, through macOS's administrator dialog) only if it's the one setup gives and nothing else is repeating, since cancelling removes every repeating event |
| Weekend Picks         | Not in setup: manage turns them on. Config only. Each Friday's picks go to `~/FamilyBrief/weekend_events/`                                                                                                                                  | The folder is part of the archive (below)                                                                                                                                                                        |
| The plugin            | The install line, `get.sh` without a flag, and `get.sh --codex` download the `stable` branch to `~/FamilyBrief/plugin`, replacing what's there only if it's Parent Recap's, and run its `install.sh` from there; zip installs unzip it there. Claude Code keeps its copy under `~/.claude/plugins`: `get.sh --claude` adds the `kinlace/parent-recap#stable` marketplace and installs it there for the Mac user, and so does the setup page, once Welcome is saved with Claude. With ChatGPT the page installs the Codex skills instead, as `install.sh --codex` does, from `~/FamilyBrief/plugin` | Removes `~/FamilyBrief/plugin` if its `.claude-plugin/plugin.json` names `parent-recap`. Runs `claude plugin uninstall parent-recap@kinlace`, then `claude plugin marketplace remove kinlace`, for each the record has and Claude Code still lists. Otherwise says to remove them with `/plugin uninstall parent-recap@kinlace` and `/plugin marketplace remove kinlace` |

## Where each secret lives

| Secret                         | Where                                                  | Uninstall                                       |
| ------------------------------ | ------------------------------------------------------ | ----------------------------------------------- |
| Gmail App Password             | Keychain `family-brief` / `gmail-imap-<address>`       | Deleted. The family deletes it at Google        |
| Claude token                   | Keychain `family-brief` / `claude-oauth-token`         | Deleted                                         |
| Anthropic API key (if used)    | Keychain `family-brief` / `anthropic-api-key`          | Deleted                                         |
| ChatGPT login                  | `~/.codex`, Codex's own                                | Not touched                                     |
| Wilma login                    | `~/.config/wilmai/config.json`, the wilma CLI's own    | Setup's profile deleted; one from before setup is not touched, and uninstall says how to delete it |
| MyClub links                   | `~/.family/config.yaml`                                | Deleted with the config                         |
| Google Calendar app file       | `~/.family/calendar_credentials.json`                  | Deleted                                         |
| Google Calendar token          | `~/.family/calendar_token.json`                        | Deleted. The family removes the access at Google |

Uninstall checks a Keychain item is there with `security find-generic-password` without `-w`, so it never reads a secret, and prints only the service and account.

## How uninstall works

`family-brief uninstall` first lists everything above that it finds, and removes nothing. Something in those places that isn't this install's stops it, before it removes anything: a launchd job with Parent Recap's label that runs another program, a config Parent Recap didn't write, a program folder or Codex skill of the same name that isn't Parent Recap's, or a run that's going. Files that only share a folder with Parent Recap's, such as a note in `~/FamilyBrief`, don't stop it: it lists them under "Left as it is" and doesn't touch them.

It removes only after the family confirms: `--confirm` with `--keep-archive` or `--remove-archive`, or, run in Terminal, its own two questions. The archive is the dated files (`<date>.md`, `<date>.raw.json`) in the archive folder and the Weekend Picks folder, and nothing else in them. It removes in this order: the launchd jobs (so nothing starts mid-way), the wake schedule, the Keychain items, the Wilma profile and the wilma CLI, Claude Code's plugin and then its marketplace, the Codex skills, the plugin copy, the archive if chosen, the config and state, the logs, the program, and the record last, which stays if anything couldn't be removed so the next try still knows what's left. Before it starts, it adds every Keychain item it found to the record, so one macOS refused to delete is found again after the config that named it is gone. Of the folders setup makes (`~/FamilyBrief`, its `weekend_events/`, `~/.family`), those left empty are removed too; a folder of the family's own that held the archive stays. It never touches the family's accounts; it ends with where they can delete the App Password and the Google Calendar access themselves.

After it, `~/.family/config.yaml` is gone, so setup starts again from the beginning on the same Mac.
