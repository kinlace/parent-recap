# Setup internals

What each setup step does on the Mac, what it writes and where, where each secret lives, and how `parent-recap uninstall` reverses it. It's for maintainers: when a setup step starts writing something new, add it here and teach uninstall to remove it, so the two stay in step. The family-facing steps are in [skills/setup/SKILL.md](../skills/setup/SKILL.md); the secrets and the data flow, in [SECURITY.md](../SECURITY.md).

## Setup's record

Every step that creates something adds it to `~/.family/install-record.json` (owner-only), through `family_brief.install_record`:

| Kind          | Added by                          | Value                                                       |
| ------------- | --------------------------------- | ----------------------------------------------------------- |
| `program`     | `install.sh`                      | The program folder, `~/ParentRecap/app` by default           |
| `logs`        | `install.sh`                      | `~/ParentRecap/logs`                                         |
| `runtime`     | `install.sh`                      | `~/ParentRecap/runtime`, which holds Parent Recap's pinned Python and Node |
| `plugin`      | `install.sh`, run from `~/ParentRecap/plugin` | That plugin copy                                 |
| `codex-skill` | `install.sh --codex`              | `~/.agents/skills/parent-recap-setup` and `parent-recap-manage` |
| `launchd`     | `parent-recap schedule install`   | Each job's plist in `~/Library/LaunchAgents`                 |
| `keychain`    | Storing a Gmail App Password      | The Keychain account, `gmail-imap-<address>`                 |
| `wilma-cli`   | Installing the wilma CLI: the setup page, or `parent-recap setup wilma` | The CLI's folder, `~/ParentRecap/wilma` by default |
| `wilma-profile` | Signing in to Wilma on the setup page, or in `setup wilma`'s Terminal window | The profile's id in the CLI's config, `<Wilma address>\|<username>`, never the password |
| `claude-plugin` | `get.sh --claude`, or the setup page once Welcome is saved with Claude | `parent-recap@kinlace`                   |
| `claude-marketplace` | The same                    | `kinlace`                                                     |

The last three go in only when setup installed them: a Wilma profile, plugin or marketplace that was already there in any form (such as a `kinlace` marketplace from an unzipped release) isn't recorded, so uninstall leaves it. `get.sh --claude` runs before the program is installed, so it writes its two kinds into the file itself.

Installs from 0.4.1 and older have no record. Uninstall then looks in the places listed below, says the record is missing, and lists what it found for the family to check before confirming. With or without a record, it checks that each item is this install's before it lists it for removal.

## Each step

The steps are in the order the setup skill's six phases (Welcome, Connect, Working, Check, First Brief, Finish) run them.

| Step                  | What it writes                                                                                                                                                                                          | How uninstall reverses it                                                                                                                                                                                       |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The setup page        | `parent-recap setup page` serves the page from the program's own files in `family_brief/page/`, on 127.0.0.1, until 30 minutes without a request, until every outcome of `parent-recap setup status` is true, or until the parent presses Finish for now after a try at Finish; then it says in Terminal that the window can be closed. It writes only through `parent-recap setup save` (the config and setup's progress, below), and the Gmail, Wilma and Claude sign-ins and the MyClub links the way their own steps keep them, below, and the first Brief's delivery in `~/.family/state.json` (First Brief, below). Its WhatsApp step reads and opens System Settings the way `setup whatsapp` does, below. "Continue in the chat" opens Claude Code at the setup skill in a Terminal window, from a script in a temporary folder removed when the page stops, and writes nothing else; for Codex it only shows what to type | Nothing of its own to reverse                                                                                                                                                                                    |
| Welcome               | Nothing                                                                                                                                                                                                 | Nothing to reverse                                                                                                                                                                                              |
| Connect: the Mac      | Whatever the family installs themselves, such as the `claude` CLI                                                                                                                                  | Left alone: they're general tools other programs use                                                                                                                                                             |
| Finding the programs  | `~/.family/programs.json` (600): where `claude`, `codex` or `node` (for a `claude` installed with npm) was found when the PATH doesn't lead to it, as in macOS's own Terminal with the family's own shell setup (fish, nix, a custom npm prefix). After the PATH, `family_brief.tools` looks in `~/.local/bin`, `~/.npm-global/bin`, `~/.nix-profile/bin`, `/opt/homebrew/bin`, `/usr/local/bin` and `/etc/profiles/per-user/<user>/bin`, then asks the login shell (`$SHELL -l -c 'command -v <name>'`, for up to 5 seconds). | Connect: install      | `install.sh`: `~/ParentRecap/runtime/python-<version>-<build>`, Parent Recap's own Python, a python-build-standalone build downloaded and checked against the checksum in `install.sh` (ADR 0011), once per pinned version, with the folder of an older version removed; `~/ParentRecap/runtime/node-v<version>`, Parent Recap's own Node, a nodejs.org build downloaded and checked the same way, which the wilma CLI runs on; `~/ParentRecap/app` (the program, its `.venv` built on that Python, and `VERSION`), `~/ParentRecap/logs` with an `install-<date>-<time>.log` of pip's output for each install, the folder `~/.family`, and the record. It says to remove the Python from Full Disk Access by hand, since a program can't. Removes the logs. Removes each Codex skill only if its `SKILL.md` has that skill's name and the installer's "installed in Codex" note |
| Connect: Wilma        | The wilma CLI, version 2.1.2, in `~/ParentRecap/wilma`: the setup page and `parent-recap setup wilma` install it when it's missing with Parent Recap's own Node and its npm (`npm install -g --prefix <folder> @wilm-ai/wilma-cli@2.1.2`, with npm's cache in a temporary folder), into a new folder `~/ParentRecap/.wilma-<random>`, which takes the place of `~/ParentRecap/wilma` only once npm has finished, so an npm that fails or is ended at the time limit changes nothing, and always run it on that Node, never on a Node or wilma CLI the Mac has (ADR 0011), with `WILMAI_NO_UPDATE_CHECK=1` so it never looks for a newer version. `install.sh` runs the same npm line on every update when a CLI of another version is there, or one left half installed while the CLI's config has a sign-in (`python -m family_brief.setup_wilma update`, with the program's umask). Its sign-in, `~/.config/wilmai/config.json`, with the Wilma password Base64-encoded, and next to it the CLI's own `wilmai-sessions.json`, its last Wilma session. The CLI writes both owner-only, and each evening run makes them and their folder owner-only if they aren't. `parent-recap setup wilma` runs the sign-in from a script in a temporary folder, removed when the step ends. The setup page writes that file itself, the way the CLI does (ADR 0008). Since the CLI's commands read every profile, it first writes the new profile alone into an owner-only temporary folder, runs the CLI's `kids list` on it there through `WILMAI_CONFIG_PATH`, and removes that folder, then adds the profile to the CLI's config, keeping its other profiles, only if the sign-in works. It reads the town list from the CLI's own copy. Either way the town goes in the config as `city`. The CLI and a profile new to its config go in the record | Removes the profile the record has from `config.json`, keeping the CLI's other profiles, with `wilmai-sessions.json`, as the CLI does when it removes a sign-in, and the file, the CLI's `version-check.json` and their folder once none are left. Removes `~/ParentRecap/wilma`, but only if it holds nothing but what npm puts there. A profile from before setup, and a wilma CLI of the Mac's own, are left alone: uninstall then prints the command to delete the profile, and says why it matters |

Later changes leave backups next to it, `config.yaml.bak-<date>`                                                                                                         | Removes the config and its backups, but only if the config reads as a Parent Recap config (it has Kids, and Gmail or email settings)                                                                             |

It also keeps the page's Welcome choice of partner until the parent's own address is known, when the page's Gmail step saves the Recipients. Once the page can read WhatsApp, it keeps the groups found there too, as `whatsapp_chats`, and in Working the Gmail senders it read, as `gmail_senders`, both for the check page. Skipping Wilma on the page also saves `wilma.enabled: false` in the config. On Welcome the page checks the AI with `claude auth status` or `codex login status`, which change nothing                                                                     | Removes it                                                                                                                                                                                                      |

In the family's Google account: the App Password          | Deletes the Keychain item (macOS may ask the family to allow it). | Connect: AI login     | Claude: `parent-recap setup claude` (or the older `scripts/setup_claude_token.py`): Keychain `family-brief` / `claude-oauth-token` (or `anthropic-api-key`). The setup page runs `claude setup-token` itself in a pseudo-terminal, reads the token from its screen, tests and stores it the same way, and writes no file; if that fails it opens the same Terminal window, from a temporary folder removed once the token is saved or the page stops, and takes the token in its own field. ## Where each secret lives

| Secret                         | Where                                                  | Uninstall                                       |
| ------------------------------ | ------------------------------------------------------ | ----------------------------------------------- |
| Gmail App Password             | Keychain `family-brief` / `gmail-imap-<address>`       | Deleted. The family deletes it at Google        |
| Claude token                   | Keychain `family-brief` / `claude-oauth-token`         | Deleted                                         |
| Anthropic API key (if used)    | Keychain `family-brief` / `anthropic-api-key`          | Deleted                                         |
| ChatGPT login                  | `~/.codex`, Codex's own                                | Not touched                                     |
| Wilma login                    | `~/.config/wilmai/config.json`, the wilma CLI's own    | Setup's profile deleted; one from before setup is not touched, and uninstall says how to delete it |
| MyClub links                   | `~/.family/config.yaml`                                | Deleted with the config                         |
| Google Calendar app file       | `~/.family/calendar_credentials.json`                  | Deleted                                         |
| Google Calendar token          | `~/.family/calendar_token.json`                        | Deleted. The family removes the access at Google |

Every Keychain item is written and read with `/usr/bin/security` (ADR 0009). Setup writes it with `add-generic-password -U … -T /usr/bin/security`, typed into `security -i` on stdin so the secret is on no command line, after deleting an item already there so the new one gets this access list. It then reads it back, and the step succeeds only if that works. The evening job and `doctor` read it with `find-generic-password -w`, giving up after 5 seconds: an item an earlier version stored with Python's `keyring` makes macOS ask for the Keychain password first, which nobody answers at night. `doctor` tells such an item apart from a missing one and says to store it again.

Uninstall checks a Keychain item is there with `security find-generic-password` without `-w`, so it never reads a secret, and prints only the service and account.

## How uninstall works

`parent-recap uninstall` first lists everything above that it finds, and removes nothing. Something in those places that isn't this install's stops it, before it removes anything: a launchd job with Parent Recap's label that runs another program, a config Parent Recap didn't write, a program folder or Codex skill of the same name that isn't Parent Recap's, or a run that's going. Files that only share a folder with Parent Recap's, such as a note in `~/ParentRecap`, don't stop it: it lists them under "Left as it is" and doesn't touch them.

It removes only after the family confirms: `--confirm` with `--keep-archive` or `--remove-archive`, or, run in Terminal, its own two questions. The archive is the dated files (`<date>.md`, `<date>.raw.json`) in the archive folder and the Weekend Picks folder, and nothing else in them. The list `ai-filter-report --held-back` writes in the archive folder (`held-back-list.txt`) is made from the archive again each time, so it goes whether the archive stays or not. It removes in this order: the launchd jobs (so nothing starts mid-way), the wake schedule, the Keychain items, the Wilma profile and the wilma CLI, Claude Code's plugin and then its marketplace, the Codex skills, the plugin copy, the archive if chosen, the config and state, the logs, the program, and the record last, which stays if anything couldn't be removed so the next try still knows what's left. Before it starts, it adds every Keychain item it found to the record, so one macOS refused to delete is found again after the config that named it is gone. Of the folders setup makes (`~/ParentRecap`, its `weekend_events/`, `~/.family`), those left empty are removed too; a folder of the family's own that held the archive stays. It never touches the family's accounts; it ends with where they can delete the App Password and the Google Calendar access themselves.

After it, `~/.family/config.yaml` is gone, so setup starts again from the beginning on the same Mac.
