# Troubleshooting

First run `~/FamilyBrief/app/.venv/bin/family-brief doctor`; it points out most problems directly. The log is `~/FamilyBrief/logs/run-stderr.log`; the last few dozen lines are usually enough. **Don't paste mail or message text from the log into the chat.**

| Symptom                                                                                        | Cause                                                                                                      | Fix                                                                                                                                                                                                                                                                                                                                                                       |
| ---------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The Brief says the summary failed, and the log has `Credit balance is too low` or `403`        | The scheduled job didn't get the Claude subscription token and fell back to an API route with no credit    | In Terminal, run `claude setup-token` again, then `scripts/setup_claude_token.py`                                                                                                                                                                                                                                                                                         |
| The Brief says the summary failed, and the log has `codex exec failed`                         | The Codex login expired, or the Codex app was removed                                                      | Open the Codex app, log in again with the ChatGPT account, then run `family-brief doctor`. Full output is in `~/FamilyBrief/logs/codex_cli_failed.txt`                                                                                                                                                                                                                    |
| The Brief says the summary failed, and the log has `timed out`                                 | Too many messages piled up at once (for example after a holiday), or Claude / ChatGPT was temporarily slow | The program retries once; if both attempts fail it sends the list of original messages instead, and it usually recovers the next day. If it happens often, raise `llm.timeout_seconds` to 600                                                                                                                                                                             |
| The Brief says Claude's or Codex's reply was cut off                                           | The model stopped partway through its reply, so the items after the cut are missing                        | Everything that arrived is in the Brief; look through that night's messages in the `~/FamilyBrief` archive for the rest. If it happens again, tell Claude or Codex "check FamilyBrief" |
| The Brief says the Google Calendar authorization expired                                       | The authorization was revoked, or the Google app is still in "Testing" (which expires every 7 days)        | In Terminal, run `scripts/setup_google_calendar.py` again. If it expires every week: with your own app, publish it as in step 4 of [Creating your own Google app](sources.md#creating-your-own-google-app); with the maintainers' file, tell the maintainers                                                                                                              |
| No Brief on some days                                                                          | The Mac was asleep at 21:00                                                                                | `family-brief schedule install` gives a `sudo pmset repeat wakeorpoweron ...` command for the user to run in Terminal (it warns first if that would replace another repeating wake schedule). launchd runs the missed job once the Mac wakes up                                                                                                                                                                                                  |
| The Brief arrives at an odd time (such as after midnight) with many network errors             | The run started as the Mac woke up, before the network was connected                                       | The program waits up to 60 seconds for the network at start; if it still happens often, check that the pmset wake time is earlier than the job time                                                                                                                                                                                                                       |
| The Brief says no Source could be read tonight                                                 | Every Source failed that night: the network was down, or a login or permission stopped working             | Each line names the Source and what to do. Run `doctor` to confirm. Once a Source reads again, the next Brief reaches back to its last good night (up to a week), so its messages aren't lost |
| At 21:00 a popup says "python3.x would like to access data from other apps"                    | The scheduled job's Python doesn't have permission to read WhatsApp yet                                    | Click Allow, or run `family-brief app-management` and drag the Python file it shows in Finder into System Settings → Privacy & Security → App Management                                                                                                                                                                                                                                  |
| After upgrading Python (brew upgrade) WhatsApp can't be read, or a Keychain prompt pops up     | The real Python path changed, so macOS treats it as a new program                                          | Click "Always Allow" on the Keychain prompt; add the new Python path to App Management; run `bash PLUGIN/install.sh` again                                                                                                                                                                                                                                                |
| A WhatsApp group's messages are missing from the Brief; doctor says the group name isn't found | The group was renamed, or replaced by a new group for the new school year                                  | Run `family-brief bg discover whatsapp-chats` and copy the new group name exactly (watch for trailing spaces and curly quotes)                                                                                                                                                                                                                                            |
| Reading WhatsApp from Terminal, Claude Code or Codex fails with `Operation not permitted`      | macOS grants permission per process, and these apps don't have it                                          | This is expected; don't give Terminal the permission. Put `bg` before the command (for example `family-brief bg discover whatsapp-chats`) to read with the scheduled job's Python. `doctor` checks this way automatically. If it still fails with `bg`, run `family-brief app-management` and drag the Python file it shows into App Management, and if that doesn't work, into Full Disk Access |
| A run stops at once with `Another FamilyBrief run is still going`                              | A Brief or Weekend Picks run is already going, for example one started by hand that is still reading      | Wait a few minutes for it to finish instead of starting it again. Two runs at once could send the Brief twice. Previews (`--dry-run`) aren't held up                                                                                                                                                                                                                       |
| "Tomorrow's timetable" is wrong in the Friday or weekend Brief                                 | On weekends Wilma returns the timetable for the next school day                                            | Fixed: the timetable is labelled with its actual date. If it's still wrong, check whether an old version is installed                                                                                                                                                                                                                                                     |
| The Wilma part is empty, or doctor says not logged in                                          | The wilma CLI login expired, or the Wilma password was changed                                             | In Terminal, run `wilma` to log in again                                                                                                                                                                                                                                                                                                                                  |
| Wilma has no timetable beyond two weeks                                                        | Wilma only publishes the near-term timetable                                                               | Expected                                                                                                                                                                                                                                                                                                                                                                  |
| The calendar fills with club events unrelated to your Kids                                     | The MyClub subscription includes the whole club's public events                                            | Add keywords from those event titles to `myclub.blocklist` in the config (case-insensitive), such as `uimaopetus`                                                                                                                                                                                                                                                         |
| The model attributes a message to the wrong Kid                                                | The group's `kid` is wrong, or the name used for the Kid isn't in `aliases`                                | Adjust `whatsapp.chats[].kid` and `kids[].aliases`                                                                                                                                                                                                                                                                                                                        |
| Personal mail unrelated to the Kids was scanned                                                | The allowlist has too broad a domain                                                                       | Remove public domains from `allowlist_domains` and use `allowlist_senders` for individual people                                                                                                                                                                                                                                                                          |
| iMessage shows "Not Delivered"                                                                 | Sending iMessage by script on macOS is unreliable                                                          | Email is already the default; keep `imessage.enabled: false`                                                                                                                                                                                                                                                                                                              |

## Upgrading

Updating the plugin itself: see [Updating](../README.md#updating) in the README.

After the plugin is updated, the program also needs syncing to `~/FamilyBrief/app`:

```bash
bash "PLUGIN/install.sh"
~/FamilyBrief/app/.venv/bin/family-brief schedule install
~/FamilyBrief/app/.venv/bin/family-brief doctor
```

`install.sh` doesn't touch the config, the Keychain or the archive.

## Uninstalling

```bash
~/FamilyBrief/app/.venv/bin/family-brief schedule uninstall
rm -rf ~/FamilyBrief/app
```

Whether to delete the config and the archive (`~/.family/`, `~/FamilyBrief/`) is up to the user. The Keychain entries (service `family-brief`) can be found by searching `family-brief` in the Keychain Access app and deleted there. The Gmail App Password can be revoked at https://myaccount.google.com/apppasswords.

If Wilma was set up, its password isn't in the Keychain but in the wilma CLI's own config file. **Always delete it**; see [Where the Wilma password is stored](sources.md#where-the-wilma-password-is-stored).
