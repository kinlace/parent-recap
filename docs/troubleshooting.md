# Troubleshooting

First run `~/ParentRecap/app/.venv/bin/parent-recap doctor`; it points out most problems directly. The log is `~/ParentRecap/logs/run-stderr.log`; the last few dozen lines are usually enough. **Don't paste mail or message text from the log into the chat.**

| The install stops with "Parent Recap couldn't download its Python" or says its checksum doesn't match | The Mac was offline, the download from GitHub was cut off, or what arrived wasn't the Python Parent Recap pins. Nothing was changed | Run the install again once the Mac is online. If the checksum still doesn't match, tell the Parent Recap team |
| The install stops with "Parent Recap couldn't install its Python packages"                    | pip couldn't install a package the program needs, often because none is ready-made for this Mac            | Run the install again. Its first line says which Mac, macOS, Python, pip and compiler it ran with; the rest is pip's full output |

| Claude Code shows a red "Auto-update failed" notice, such as "no write permission to npm prefix" | Claude Code was installed with npm (or Homebrew) into a folder this Mac user can't write, so it can't update itself | This comes from Claude Code itself and doesn't affect Parent Recap. ## Testing the scheduled job

`family-brief schedule run-now` asks launchd to start the installed evening job right now, so it runs with the job's own Python, `PATH`, environment and log files, and prints where the logs are. It doesn't wait for the Brief, and it sends it to every Recipient, like the evening one. `--weekend` starts the Weekend Picks job instead. If the job isn't installed it points to `family-brief schedule install`, and if a run is already going it says so. `family-brief bg run` is different: a one-off job with the same Python, not the scheduled job itself.

## Upgrading

Updating the plugin itself: see [Updating](../README.md#updating) in the README.

After the plugin is updated, the program also needs syncing to `~/ParentRecap/app`:

```bash
bash "PLUGIN/install.sh"
~/ParentRecap/app/.venv/bin/parent-recap schedule install
~/ParentRecap/app/.venv/bin/parent-recap doctor
```

`install.sh` doesn't touch the config, the Keychain or the archive.

## Uninstalling

Tell Claude or Codex "uninstall Parent Recap", or run this in Terminal:

```bash
~/ParentRecap/app/.venv/bin/parent-recap uninstall
```

It first lists everything setup created on this Mac (the scheduled jobs, the wake schedule, the program and its logs, the config and state, the Keychain items, the Codex skills and the plugin copy, and the wilma CLI, its Wilma sign-in and the Claude Code plugin when setup installed them), asks whether to keep the archive of past Briefs, and removes only after you confirm. macOS may ask you to allow deleting each Keychain item, and asks for your Mac password to cancel the wake schedule. If it finds something in those places that isn't this install's, such as an older install's scheduled job, it stops and removes nothing. What it does step by step is in [setup-internals.md](setup-internals.md).

It never touches your accounts. Delete the Gmail App Password yourself at https://myaccount.google.com/apppasswords, and if you used Google Calendar mode, remove Parent Recap's access at https://myaccount.google.com/connections. If you installed the Claude Code plugin yourself, before setup, uninstall leaves it: remove it in Claude Code with `/plugin uninstall parent-recap@kinlace` and `/plugin marketplace remove kinlace`.

The Wilma password isn't in the Keychain but in the wilma CLI's own config file. Uninstall removes the sign-in setup made there, and the wilma CLI if setup installed it. If you had signed in with the wilma CLI before setup, that sign-in and the CLI stay, and uninstall says so: **always delete them** if you only used them for Parent Recap; see [Where the Wilma password is stored](sources.md#where-the-wilma-password-is-stored).
